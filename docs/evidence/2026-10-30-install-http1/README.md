# macOS / Linux 安装下载 HTTP/2 错误修复

用户在线安装报告 `curl: (16) Error in the HTTP2 framing layer`，随后脚本提示 `下载发布包失败：latest`。

## 原因与修改

- 旧版安装脚本的两个 curl 命令会自动协商 HTTP/2；`--retry 3` 不覆盖 curl 16 等传输错误，下载失败后立即退出。
- 现场无法复现用户网络的 HTTP/2 故障；同一 Latest URL 的 HTTP/2 和 HTTP/1.1 请求均返回 HTTP 200，v1.2.0 资产完整。具体是客户端、代理还是远端连接触发错误，尚未确认。
- `scripts/install.sh` 中的发布包和校验文件统一使用 HTTP/1.1。连接超时为 15 秒，单次传输上限为 600 秒；对连接/传输错误及 408、429、500、502、503、504 最多重试 3 次，404 等错误直接停止。
- 下载先写入 `.part`，失败删除残片；完整下载后继续校验 SHA-256。修改版本指针和停止旧服务仍在成功校验之后。
- README、安装文档及 v1.2.0 发布说明中的入口命令同样使用 `--http1.1`。修复由在线 `main/scripts/install.sh` 生效，继续安装已发布的 v1.2.0，无需覆盖发布标签或成品包。

## 验证

`sh -n scripts/install.sh` 通过。[安装回归](installer-tests.tap)共 10 项，9 项通过、1 项因未指定成品包跳过：

- 注入不支持 HTTP/2 的 curl 替身，强制检查发布包及校验文件均使用 HTTP/1.1。
- 注入不完整传输、HTTP 503、连接读取失败，确认重试成功且残片不会沿用。
- 注入连续 curl 16，确认总共尝试 4 次，原服务 PID、版本、配置和密码不变。
- HTTP 404 只尝试一次，不创建安装；错误 SHA-256 继续被拒绝。
- 首次安装、重复安装、升级、后台启停及 PID 归属保护通过。

所有测试使用隔离安装目录与动态端口。

真实 v1.2.0 Latest 成品包通过 HTTP/1.1 下载，SHA-256 校验通过；使用该包运行[成品包回归](production-tests.tap)，10 项全部通过，包括生产页面资源、登录及 Git/Worktree API。
