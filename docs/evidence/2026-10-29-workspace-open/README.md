# 多仓库目录打开性能回归

测试目录为用户指定的 `/regression/im-workspace` 与 `/regression/project-maikoo/`。仅读取目录和 Git 状态，未修改两个目录的文件、分支、暂存区或业务服务。

## 确认的原因

- IM 目录发现 20 个独立仓库；Maikoo 目录发现 1 个共享仓库下的 11 个工作目录。原打开流程逐个探测仓库，并等待文件监听预扫描结束。
- 工作区变更数量、最近目录统计及文件树只需要文件清单和分类，却都计算了未暂存与已暂存的逐行差异。文件树查询还会读取所有仓库，包括当前展开目录无关的仓库。
- 打开后的文件树会再次读取状态；最近目录统计也会增加同时发生的扫描。问题位于后端读取路径，界面渲染不是本次确认的主要耗时来源。

## 修改范围与历史行为

- `workspace-service.ts`：每批最多探测 4 个目录；已确认仓库的分支、HEAD 与共享仓库身份并行读取。保留发现深度、数量上限、别名去重及稳定排序。
- `watch-service.ts`：监听预扫描每批最多读取 4 个目录，保留忽略规则、数量限制及停止监听行为。
- `git-service.ts`：数量统计可跳过 numstat；详细状态仍包含行统计，干净工作目录跳过无用 diff；合并同一仓库同时发生的同类状态查询。失效后的旧查询不能恢复过期缓存。
- `app.ts`：数量与树标记使用文件状态清单；展开目录只查询相关仓库。文件树仍主动读取磁盘状态，没有通过延长缓存掩盖外部修改。

## 实测结果

同机浏览器首轮对比，最近目录统计启用，测量“点击打开 → 根文件树可见”；每个目录修复前后各一轮，磁盘缓存及并行 I/O 会影响绝对耗时。

| 目录 | 修复前 | 修复后 | 减少 |
|---|---:|---:|---:|
| IM workspace | 4.507 秒 | 3.168 秒 | 30% |
| Maikoo | 1.803 秒 | 1.449 秒 | 20% |

修复前后的仓库 ID、逻辑路径、变更数量及根目录 Git 标记完全一致，浏览器运行错误为 0。原始对比摘要见 [comparison.json](comparison.json)。

另以独立会话各执行 3 轮回归，核对打开、根文件树、全部仓库详细状态、变更数量、目录展开、`.git` 隐藏及关闭工作区。两目录各轮状态摘要一致；不包含浏览器最近目录统计时，打开至根树返回的中位数分别为 1.703 秒、0.442 秒。见 [regression.json](regression.json)。

可重复执行：

```bash
npm run build
node scripts/workspace-open-regression.mjs \
  /regression/im-workspace \
  /regression/project-maikoo/ \
  --rounds=3 --output=/tmp/workspace-open-regression.json
```

`npm run check` 通过：类型检查、10 个测试文件 / 62 项测试及生产构建。新增用例覆盖轻量/详细状态、并发合并、失效竞态、失败重试、发现限制与目录查询范围。当前本地 PM2 `code-workspace` 服务已重启以加载后端修复，并以独立会话再次打开两个实际目录验证。

公开记录中的本机绝对路径已替换为 `/regression/*` 别名；复现时请使用本机实际目录。原始计时和结果签名保持不变。
