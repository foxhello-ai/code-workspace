# 公开仓库安全说明

2026-10-26 的检查覆盖当前受控文件、全部远程分支与标签的可达 Git 历史、验收截图，以及历史 Release 安装包和 Actions 构建产物。

## 处理内容

- 删除固定生产默认密码。没有显式配置 `APP_PASSWORD` 时拒绝启动；安装脚本继续使用加密随机数生成密码。测试中的示例密码不用于生产。
- 将需求文档中的个人磁盘路径、真实项目和工作区名称替换为通用示例；历史提交中的个人邮箱改为已有 GitHub noreply 地址。
- PM2 默认仅监听本机地址，外部监听需显式设置 `HOST`。
- 忽略本地环境文件和常见凭据文件；新增空白 `.env.example`，其中没有可直接使用的密码。
- 使用 Gitleaks 扫描历史，并增加公开仓库的持续检查。验收报告中的三个 SHA-256 文件校验值使用限定到文件及行格式的例外，其他检测规则继续生效。
- 已清除包含旧默认密码的三个旧版 Release，以及旧 Actions 记录、附件和构建缓存。旧版本标签保留脱敏后的源码历史；成品安装使用修复版本。

项目自身的公开 GitHub/下载链接、开源依赖网址、localhost，以及测试中用于验证 URL 脱敏的虚构凭据不属于生产凭据，予以保留。

验证结果：43 项应用测试、7 项真实成品包安装与进程管理检查通过；重写并推送全部分支与标签后，通过全新远程镜像克隆复查，Gitleaks 和已知敏感值检查均未发现残留。13 张验收截图已检查。

## 安装用户需要处理的事项

如果曾使用旧版固定默认密码，应修改安装配置中的 `APP_PASSWORD`，再重启服务。升级会保留原配置，不会自动轮换密码。在其他系统复用过的密码也应轮换。

macOS/Linux 配置位于 `~/.config/code-workspace/config.env`，Windows 位于 `%LOCALAPPDATA%\CodeWorkspace\config\config.json`。源码运行使用未提交的 `.env` 或环境变量。

## 历史清理边界

历史重写会改变提交 ID 和标签目标。已有 clone 应重新克隆，或先保留未提交工作，再按新历史恢复；不要将旧分支合并回仓库。

重写远程分支及标签后，GitHub 仍可能保留旧提交 SHA、缓存视图或其他人的 fork/clone。彻底移除 GitHub 缓存需要由仓库拥有者联系 [GitHub Support](https://support.github.com/contact)；仓库侧无法删除其他人的副本。已经公开的密码应视为失效，不能因为历史重写而继续使用。

本次检查确认旧敏感 blob 仍可通过对象 SHA 访问。因此“当前分支和标签的历史已清理”不等于“GitHub 缓存已物理删除”；后者需要平台支持处理。
