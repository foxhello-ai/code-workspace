# 轻量级代码工作区任务安排计划

## 1. 计划信息

- 产品代号：Code Workspace
- 计划版本：V1.0
- 计划日期：2026-07-19
- 依据文档：`docs/detailed-design.md` 及已确认的需求基线
- 交付范围：文件树、Monaco 编辑、Git 历史、Git Diff、外部文件变化同步
- 后续扩展（2026-10-22）：B-009/B-010 阶段 A 已实现，阶段 B 后续实施，见[第 13 节](#13-远程提交图与-worktree-后续任务)。下列 MVP/V1.1 历史任务状态不代表扩展范围已完成。

## 2. 交付原则

- 先建立路径安全、文件版本和 Git 解析等底层能力，再开发完整 UI。
- 每个里程碑必须有自动化测试和可演示结果，不把测试集中留到最后。
- Git 功能在 MVP 中只读。
- 不开发 Codex 会话、终端、AI 或任意命令执行能力。
- 外部文件变化与编辑冲突属于核心主流程，不作为后期优化。
- 时间以人日估算；1 人日代表一名熟悉技术栈的工程师一个工作日。

## 3. 团队与估算基线

推荐配置：

- 前端工程师：1 人
- 后端工程师：1 人
- 全栈/测试工程师：1 人
- 产品验收：兼职参与每个里程碑

估算：

|---|---:|

| 工作区、路径安全和文件 API | 8 |

| Git 状态与修改列表 | 6 |

按 3 人并行、考虑任务依赖和联调，预计 5～6 周完成可发布 MVP。单人开发预计 12～14 周。

## 5. 详细任务分解

### M0：范围冻结与技术验证

目标：消除会影响架构和排期的不确定项。

任务：

- [ ] 确认首发平台：Linux、macOS；决定 Windows 是否延期。
- [ ] 确认工作区选择方式：路径输入或系统目录选择器。
- [ ] 冻结文件和 Diff 大小阈值。
- [ ] 冻结文件操作范围：只读树或包含新建、重命名、删除。
- [ ] 验证 Monaco 在目标浏览器加载、Diff 和大文件行为。
- [ ] 验证 chokidar 在外部原子替换、批量生成和重命名时的事件序列。
- [ ] 验证 Git porcelain v2、`-z`、根提交和 merge commit 的解析方案。
- [ ] 建立包含特殊文件名、空仓库、冲突和大仓库的测试 fixtures。
- [ ] 记录 ADR-01～ADR-08 的最终结论。

交付物：

- 冻结后的设计参数。
- 技术验证记录。
- 测试仓库生成脚本或固定 fixtures。

验收：

- 所有“开发前冻结参数”已有明确结论。
- Monaco、watcher 和 Git 方案均通过最小原型验证。
- 范围中明确不存在 Codex 会话、终端和 AI 功能。

依赖：无。

前端任务：

- [ ] 建立错误提示、加载状态和空状态基础组件。

共享任务：

### M2：工作区、文件树和路径安全

后端任务：

- [ ] 实现 WorkspaceService 的 open/get/close。
- [ ] 实现工作区路径规范化和 Git 仓库检测。
- [ ] 实现 PathGuard：路径穿越、`.git`、符号链接逃逸防护。
- [ ] 实现目录直接子节点读取和自然排序。
- [ ] 实现隐藏文件、ignored 文件过滤参数。
- [ ] 实现单目录超大节点分页。
- [ ] 实现文件 stat、UTF-8、二进制和大小分类。
- [ ] 实现文件内容读取 API。

前端任务：

- [ ] 实现打开/关闭工作区流程。
- [ ] 实现文件树懒加载、展开、折叠和刷新。
- [ ] 实现当前选择和“在树中定位”的基础能力。
- [ ] 实现非 Git 工作区提示。
- [ ] 实现二进制、未知编码和大文件提示页。

测试任务：

- [ ] PathGuard 安全单测。
- [ ] 特殊文件名、不可读路径、符号链接集成测试。
- [ ] 10 万文件仓库和单目录 1 万节点的基准测试。

验收：

- 可以打开普通目录和 Git 仓库。
- 目录按需加载，`.git` 不可访问。
- `../`、绝对路径注入和外链符号链接均被拒绝。
- 二进制或超限文件不会被错误送入文本编辑器。

依赖：M1。

目标：建立可靠的文本编辑闭环。

- [ ] 实现同目录临时文件与原子替换。

- [ ] 实现 409 `FILE_VERSION_CONFLICT`。

前端任务：

- [ ] 集成 Monaco Editor。
- [ ] 实现多标签页、激活、关闭和标签复用。
- [ ] 实现语言模式、查找替换、自动换行和 Minimap 设置。
- [ ] 实现 dirty 标识和保存快捷键。
- [ ] 实现关闭标签、关闭工作区前的未保存确认。
- [ ] 保存并恢复光标、选择和滚动位置。
- [ ] 将 Monaco buffer 与服务端 Query cache 隔离。
- [ ] 处理保存成功、失败和 409 冲突状态。

测试任务：

- [ ] LF、CRLF、mixed、无末尾换行测试。
- [ ] 同一文件并发写入冲突测试。
- [ ] 多标签保存和关闭确认 E2E。
- [ ] 1 MiB 普通文件打开和编辑性能测试。

验收：

- UTF-8 文件可以打开、修改和保存。
- 未保存标识准确，关闭时不会丢失内容。
- 磁盘版本变化后普通保存被拒绝，不能静默覆盖。
- 保存不引入非用户预期的换行符变化。

前端任务：

- [ ] 实现 WebSocket 连接、心跳和指数退避重连。
- [ ] 按事件失效受影响的文件树节点。
- [ ] clean 标签外部变化后自动加载并保留视图位置。
- [ ] dirty 标签外部变化后保留 buffer 并显示冲突标识。
- [ ] 实现编辑器内容与磁盘内容的 Conflict Diff。
- [ ] 实现“使用磁盘版本”“保留编辑器版本”“暂不处理”。
- [ ] 处理外部删除和重命名。
- [ ] 实现无法补发事件时的全量状态重同步。

测试任务：

- [ ] 外部 change/add/delete/rename 集成测试。
- [ ] dirty 与 clean 标签事件矩阵 E2E。
- [ ] 原子保存、批量生成 1000 文件和事件风暴测试。
- [ ] WebSocket 断线、后端重启和序号缺口测试。

验收：

- 普通外部变化 P95 在 1 秒内显示。
- dirty 内容不被任何外部事件覆盖。
- 外部删除后标签内容仍可恢复或另存。
- 重连后界面能检测并修正遗漏状态。

依赖：M3；后端 watcher 基础可与 M3 前端并行。

### M5：Git 状态与修改面板

目标：准确展示当前仓库和修改分类。

后端任务：

- [ ] 实现 GitRunner 的参数白名单、超时和输出限制。
- [ ] 实现 Git 可用性、仓库根、分支、HEAD、Detached HEAD 检测。
- [ ] 实现 porcelain v2 `-z` 状态解析。
- [ ] 解析 staged、unstaged、untracked、rename 和 conflict。
- [ ] 实现 Git 状态缓存、revision 和失效机制。
- [ ] 实现按需 numstat 统计。

前端任务：

- [ ] 实现顶部当前分支、HEAD 和 clean 状态。
- [ ] 实现冲突、已暂存、未暂存、未跟踪分组。
- [ ] 实现修改类型和增删行数展示。
- [ ] 将 Git 状态映射到已加载文件树节点和祖先目录。
- [ ] Git 不可用时禁用 Git 页面且不影响编辑器。

测试任务：

- [ ] 空仓库、普通分支和 Detached HEAD。
- [ ] staged + unstaged 同文件、rename、delete、untracked、conflict。
- [ ] 包含空格、中文、换行或前导短横线的文件名。
- [ ] Git 超时和输出超限错误。

验收：

- Git CLI 状态与 UI 分类一致。
- 同一路径同时 staged/unstaged 时不会被错误去重。
- 文件树状态随外部 Git 操作自动刷新。
- Git 查询失败不影响文件编辑和未保存内容。

依赖：M2、M4 的事件失效能力；可与 M3 部分并行。

### M6：Git Diff

后端任务：

- [ ] 实现 `working`、`staged`、`all` Diff。

- [ ] 实现根提交相对 Git 空树的 Diff。
- [ ] 实现左右版本文件内容读取。
- [ ] 处理新增、删除、重命名和二进制文件。
- [ ] 实现单文件与整次 Diff 的大小、超时和截断策略。
- [ ] Diff 响应关联 Git revision。

前端任务：

- [ ] 集成 Monaco Diff Editor。
- [ ] 实现并排/行内模式切换。
- [ ] 明确展示基准版本和目标版本。
- [ ] 实现文件列表、增删统计和上下一个修改。
- [ ] 实现二进制、截断和超限占位状态。
- [ ] Git revision 变化后标记 Diff 过期并支持刷新。
- [ ] 管理 Diff Monaco model 生命周期。

测试任务：

- [ ] 三种工作区 Diff 与 Git CLI 结果对照。
- [ ] 新增、删除、重命名、二进制、换行符变化。
- [ ] 根提交、普通提交、merge commit。
- [ ] 大型 Diff 不阻塞其他文件查看。

验收：

- 页面始终明确显示“谁与谁比较”。
- staged、unstaged、all 的内容与 Git 语义一致。
- 特殊文件状态正确，不把截断内容冒充完整 Diff。
- 状态变化后旧 Diff 有明确过期提示。

依赖：M5；commit Diff 部分依赖 M7 的提交模型，可先约定接口并行实现。

### M7：Git 历史

目标：浏览当前分支历史、提交详情及提交文件。

后端任务：

- [ ] 实现当前分支历史游标分页，默认 50、最大 100。

- [ ] 实现提交详情、正文、父提交和文件统计。

- [ ] 实现不可变提交详情缓存。
- [ ] 返回历史查询时的 HEAD，用于检测分页漂移。

前端任务：

- [ ] 实现历史列表和加载更多。

- [ ] 实现提交详情及修改文件列表。
- [ ] 点击文件打开 commit Diff。
- [ ] HEAD 变化时提示历史刷新，不打断当前阅读。

测试任务：

- [ ] 1 万提交仓库分页性能。

## 8. 测试与质量计划

### 8.1 持续集成门禁

每次合并必须通过：

- lint
- TypeScript typecheck
- 单元测试
- 后端集成测试
- 前端组件测试
- production build

主分支每日或关键里程碑执行：

- Playwright E2E
- 临时 Git 仓库矩阵测试
- 性能冒烟测试
- 依赖安全扫描

### 8.2 覆盖重点

覆盖率数字不是唯一目标，以下模块要求分支用例完整：

- PathGuard
- 文件版本冲突
- Git 状态和历史解析器
- Diff 基线选择
- watcher 事件状态机
- 前端 dirty/external 状态转换

建议整体单元测试行覆盖率不低于 80%，上述关键模块不低于 90%。

### 8.3 缺陷等级

- P0：内容丢失、越权访问工作区外、仓库破坏、应用无法启动。
- P1：核心功能错误、Diff 语义错误、冲突处理失效、频繁崩溃。
- P2：有绕行方案的交互或兼容问题。
- P3：视觉、文案和低影响优化。

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 文件监听事件在不同系统表现不同 | 高 | 高 | M0 原型；事件合并；HTTP 重同步兜底 |
| dirty 内容被外部变化覆盖 | 中 | 极高 | version 校验；状态机；专项 E2E |

| Diff 左右内容与 scope 不一致 | 中 | 高 | 固定语义表；CLI 对照集成测试 |
| 符号链接导致目录越界 | 中 | 极高 | realpath 校验；新建父路径校验；安全测试 |
| Monaco 大 model 内存增长 | 中 | 中 | model 生命周期管理；大文件只读；内存基准 |

| 文件名/提交信息解析异常 | 中 | 高 | 全程 NUL 分隔；特殊字符 fixtures |

## 10. MVP 验收清单

### 工作区与文件树

- [ ] 可以打开普通目录和 Git 仓库。
- [ ] 目录按需展开，根目录首次展示满足性能目标。
- [ ] `.git` 和工作区外路径不可通过 API 访问。
- [ ] 外部新增、删除和重命名能更新文件树。

### Monaco 编辑

- [ ] UTF-8 文本文件可以打开、修改和保存。
- [ ] 多标签、dirty 标识和关闭确认正确。
- [ ] LF/CRLF 和末尾换行不被意外改变。
- [ ] 二进制、未知编码和大文件按规则处理。

### 外部文件变化

- [ ] clean 标签自动同步磁盘内容。
- [ ] dirty 标签保留缓冲区并提示冲突。
- [ ] 外部删除后内容仍可恢复。
- [ ] 断线或服务重启后可以重新校验状态。

### Git 状态和 Diff

- [ ] staged、unstaged、untracked 和 conflict 分类准确。
- [ ] working、staged、all Diff 语义准确。
- [ ] 新增、删除、重命名和二进制文件正确展示。
- [ ] Diff 明确标识双方，过期时有提示。

### Git 历史

- [ ] 默认加载最近 50 条并可继续加载。
- [ ] 提交详情、父提交和文件列表准确。
- [ ] 根提交和 merge commit 对比基线正确。
- [ ] 点击提交文件可以打开对应 Diff。

### 安全与稳定性

- [ ] 路径穿越、符号链接逃逸和 Git 参数注入测试通过。
- [ ] 保存竞态只能产生成功或 409，不能静默覆盖。
- [ ] Git/watch 服务异常不导致未保存内容丢失。
- [ ] 默认服务仅监听本机地址。
